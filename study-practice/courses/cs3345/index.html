/ Leftist Heaps

Leftist Heaps

pp. 241–245

Question

Your answer

Select a subtree, then an L/R position; or drag it there. Replacing a child leaves that subtree on the board.

Worked solution

    Rules & editing
    • Min-heap: each parent is no greater than its children. A leftist heap need not be complete or balanced.
    • NPL(null) = −1; NPL(node) = 1 + min(NPL(left), NPL(right)). Zero or one child gives NPL = 0.
    • Leftist property: NPL(left) ≥ NPL(right).
    • Merge retains the smaller root, recursively merges its right subtree with the other heap, then swaps children only if the left NPL is smaller. Equal NPLs keep their order.
    • Insert merges a singleton; DeleteMin merges the removed root’s two subtrees.
    • Selecting a node moves its entire subtree. L/R positions accept it; an occupied position releases its previous subtree. Make Root detaches the selected subtree without attaching other components automatically. Separate Node releases its children. Escape clears selection.
    • Generated keys are distinct. For equal keys, the first heap argument retains the root; equal NPLs never cause a swap.
    / Binomial Trees & Binomial Queues

    Binomial Trees & Binomial Queues

    p. 252, pp. 253–259, p. 261

    Question

    Your answer

    Select or drag the tree you believe should become a child, then attach it to your chosen parent root with the target beside it. Links must join equal-order trees and preserve min-heap order. Click Place All Trees when the forest is complete.

    Unplaced trees & carries
    Final destination slots

    Worked solution

      Rules
      • B₀ is a singleton. Bₖ contains 2^k nodes; its root’s children have orders k−1 through 0, in decreasing order.
      • Only equal-order trees may be linked. Keep the smaller root as parent; the other tree becomes its first child, producing a carry of the next order.
      • A completed queue contains at most one tree of each order. With three trees at an order, keep any one and link the other two. Any valid carry choice is accepted.
      • Insert merges a singleton. DeleteMin removes the smallest root and merges its released child trees with the remaining queue.
      • Merge, DeleteMin, scanning roots for FindMin, and worst-case Insert take O(log N). Insert takes O(1) average time; FindMin takes O(1) when a minimum is maintained separately.
      • Generated keys are distinct. Select a tree to use as the child and attach it beneath an equal-order parent root. The smaller root must remain parent. Use Undo or Redo to review links and placement; Escape clears selection.
      • Use Place All Trees only when the current forest is complete. For sequential insertion, place each queue before introducing the next key; all stages are graded together.
      / Binary Heaps

      Binary Heaps

      pp. 225–232, 234–237

      Question

      Your answer

      Click or drag two array positions to swap values. To move a value into a vacancy, select the empty position and an occupied position.

      Worked solution

      Rules

      Use 1-based heap indices. Parent(i) = floor((i − 2)/d) + 1 for i > 1; the root has no parent. Children run from d(i − 1) + 2 through d(i − 1) + d + 1, restricted to occupied positions ≤ n. Binary heaps use d = 2. A min-heap is complete and each parent is no greater than its children. Ties choose the lowest-index child; equal values do not swap. For Insert, Delete Min, and Build Heap, edit the array directly and match the specified algorithm result.
